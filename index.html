Antes de empezar

Un minuto de preparación
te ahorra problemas.

GitHub sirve para guardar y compartir versiones de tu trabajo. Antes de subir nada, comprueba que tienes la carpeta adecuada y que no vas a incluir archivos temporales enormes.

01

Encuentra la carpeta raíz

Es la carpeta principal del proyecto: dentro suelen estar Assets, Packages y ProjectSettings. No elijas solo la carpeta Assets.

02

Guarda y cierra Unity

Guarda la escena y los cambios. Cerrar el Editor mientras preparas la primera subida ayuda a evitar archivos en uso.

03

Instala GitHub Desktop

Descárgalo desde desktop.github.com e inicia sesión con tu cuenta de GitHub. Si aún no tienes cuenta, créala en github.com.

Lo importante: sí subiremos Assets, Packages y ProjectSettings. No subiremos Library, Temp ni Obj: Unity puede volver a generarlas y ocupan mucho espacio.
Sigue estos seis pasos

De tu ordenador
a tu repositorio.

Un repositorio es como una carpeta del proyecto guardada en GitHub, con un historial de cambios. Las pantallas dibujadas aquí son ejemplos; los botones pueden cambiar ligeramente según la versión de GitHub Desktop.

01

Localiza la carpeta del proyecto

Abre el Explorador de archivos (Windows) o Finder (Mac). Busca la carpeta que contiene Assets, Packages y ProjectSettings. Esa carpeta completa es la que vamos a guardar. Si no encuentras alguno de esos nombres, abre el proyecto desde Unity Hub y revisa su ubicación.

02

Crea el repositorio local

Abre GitHub Desktop y ve a File → Add Local Repository…. Elige la carpeta raíz de tu proyecto. Si te avisa que no es un repositorio, selecciona la opción para crear uno allí. Si ese aviso no aparece, usa File → New repository… y confirma que la ubicación sea la carpeta existente de Unity, no una carpeta nueva dentro de ella.

03

Elige la plantilla Unity

Pon un nombre para el repositorio y comprueba la ruta. En Git ignore, selecciona Unity si aparece. Esta plantilla evita subir carpetas temporales grandes. Si ya creaste el repositorio y no te ofreció la plantilla, puedes añadir el archivo .gitignore de Unity.gitignore antes de continuar. Pulsa Create repository.

04

Guarda tu primera versión

Verás una lista de archivos. Revisa que aparezcan tus carpetas del proyecto y que no aparezcan Library ni Temp. Abajo, escribe un resumen sencillo, por ejemplo Primera versión del proyecto, y pulsa Commit to main. Un commit es una foto guardada de cómo está tu proyecto en ese momento.

05

Publica en GitHub

Pulsa Publish repository. Comprueba el nombre y deja marcada la opción Keep this code private para que el proyecto solo sea visible para ti y las personas que invites. Cuando quieras compartirlo, podrás cambiarlo a público. Pulsa el botón para terminar: tus archivos ya estarán en GitHub.

06

Sube cada nuevo avance

Cuando vuelvas a trabajar: abre el proyecto en Unity, haz cambios y guarda. Abre GitHub Desktop, escribe un resumen del cambio y pulsa Commit to main. Después pulsa Push origin para enviar ese commit a GitHub. Repite estos dos botones cada vez que quieras guardar una nueva versión en la nube.

Tranquilo: es normal

Si algo no sale,
prueba esto.

Estos son los tropiezos más comunes en la primera subida. No borres carpetas ni cambies ajustes al azar: primero identifica qué está pasando.

Veo cientos de archivos o tarda mucho

Comprueba que se esté usando la plantilla Unity y que no aparezcan carpetas como Library, Temp o Obj. Si ya se añadieron al primer commit, detente antes de publicar y corrige el .gitignore.

El archivo es demasiado grande

GitHub bloquea archivos individuales de más de 100 MB. No intentes subir compilaciones o archivos grandes sin revisar. Para archivos de arte muy pesados existe Git LFS, pero puedes empezar excluyendo Builds y otros archivos generados.

No encuentro «Publish repository»

Primero crea un commit: escribe un resumen y pulsa Commit to main. Después aparecerá la opción para publicar el repositorio. Revisa también que hayas iniciado sesión en GitHub Desktop.

¿Privado o público?

Si estás aprendiendo o tu juego aún no está listo para compartir, elige privado. Un repositorio público puede ser visto por cualquiera; no subas contraseñas, claves ni datos personales.

¡Listo! Tu proyecto ya tiene respaldo.

Ahora puedes volver a subir avances cuando quieras y consultar el historial para ver cómo fue cambiando tu juego.
